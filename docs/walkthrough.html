AI Detective

How the workshop app works, what the “RAG” actually does, and where to change things. For the MADT Expo team.

Players take the role of an AI Detective. Each of five cases shows them a question, a set of retrieved evidence, and an AI’s answer — and asks them to decide whether the AI got it right or hallucinated. A projector shows the room’s live “% of you were fooled” stats, and the facilitator drives a reveal at the end.

The whole thing is one Next.js app served from a laptop. Players join over the venue wifi. No accounts, no database, no cloud.

01 — The thing your team will ask aboutWhat the retrieval actually does

Here is the moment the entire workshop is built around. On the player’s screen, documents resolve one by one:

🔍 กำลังค้นหาจากแฟ้มคดี… apollo_17_mission_record.pdf ✓ พบเอกสาร iss_crew_rotations_1998_2025.csv ✓ พบเอกสาร crewed_missions_2026.log ✗ ไม่พบเอกสาร 🤖 คำตอบของ AI “ไม่มีครับ มนุษย์กลุ่มสุดท้ายที่เดินทางออกไปไกลกว่าวงโคจร ระดับต่ำของโลกคือลูกเรือ Apollo 17 ในเดือนธันวาคม 1972…”

Two documents found. One missing — the 2026 mission log. And then the AI answers anyway, fluently and confidently, from what it already “knew.” It never says “I don’t have 2026 data.” It just fills the hole.

That’s the lesson, made visible: a hallucination is the shape of a missing document. Players don’t just learn that AI is sometimes wrong — they watch why.

02 — Be clear about this before the demoThe RAG is simulated, on purpose

Read this first

There is no live model and no vector database in the app today. The retrieval UI is real and data-driven, but the AI’s answer is pre-written in the content file. Nothing queries an LLM at runtime.

This was a deliberate call, not a shortcut, and it’s worth defending to the team because it will come up:

  • The reveal is a group moment. The facilitator stands up and says “here is exactly what the AI got wrong.” If twenty players each got a slightly different generated answer, there is no “exactly.” The shared moment fractures.
  • A live model might refuse to hallucinate. Modern models are increasingly willing to say “the case file doesn’t contain that.” Your carefully-built trap may simply not spring — in front of prospective students. A demo that no-shows is worse than no demo.
  • Rigging a live model is worse than not using one. You could prompt a model to never admit ignorance. But a workshop about AI credibility cannot afford a rigged demo that leaks.

So: the mechanism is honest and the lesson is real, but the answer is scripted. Say that out loud in the room if anyone asks — it costs nothing and it’s in keeping with the whole point of the exercise.

What actually happens, step by step

1content/cases.ts holds the case, including a docs[] array — the “knowledge base.” Each doc has a found: true | false flag.
2<Retrieval> walks that array and reveals one doc every 600ms, printing ✓ retrieved or ✗ NOT FOUND from the flag. This part is genuinely data-driven — flip a flag, the trace changes.
3When the trace finishes, getAIAnswer(caseId, lang) is called. Today it returns the aiAnswer string from the same content file. This is the only faked step.
4The AI’s answer renders, then the Case File (found docs only), then the four verdict options.
5The player commits. The answer is POSTed to the server, scored, and folded into the projector’s live stats.

Note step 4: a document with found: false renders nothing at all. You can’t show the contents of a document the AI failed to retrieve — that would give the game away.

03 — For whoever wants to make it realThe swap seam

All the fakery is behind one function, in one file. It’s already async even though it does no I/O today — precisely so a real model call can drop in without touching any calling code.

// lib/ai-answer.ts

export async function getAIAnswer(caseId: string, lang: Lang): Promise<string> {
  const c = getCase(caseId)
  if (!c) throw new Error(`unknown case: ${caseId}`)
  return c.aiAnswer[lang]          // ← replace this line
}

To go live, you’d replace that return with a real call — embed the case’s found: true docs, retrieve top-k, stuff them into the prompt, and generate. The retrieval gap is what makes it hallucinate: you simply never index the missing document.

One catch, so nobody is surprised

getAIAnswer is currently imported into a client component. A real model call needs an API key, which can’t ship to the browser — so going live also means adding a small server route (e.g. /api/ai-answer) and having the client fetch it. It’s still a contained change, but it’s two files, not one. Don’t let anyone promise the team it’s a one-liner.

If you do go live, you’ll want to keep a pre-written fallback for exactly the failure this design was avoiding: if the model declines to hallucinate on the day, you fall back to the scripted answer and the workshop still runs.

04 — Where the team will want to editAdjusting the cases

Everything a non-engineer needs is in one file: content/cases.ts. Thai and English sit side by side. No code changes, no rebuild of anything else.

The test suite enforces the rules that matter, so a bad edit fails loudly instead of surfacing on the projector:

RuleWhy it’s enforced
Exactly 4 options, exactly one correct: trueEvery case must have one defensible answer. You’re revealing these on a projector — an arguable answer is the worst outcome.
Every th and en string non-emptyNo half-translated case reaching a Thai-speaking room.
Real (non-fictional) docs must cite a sourceUrlContent integrity — see below.
Cases 1–3 have exactly one missing doc; cases 4–5 have noneThat’s the teaching arc. See section 05.

Run npx vitest run content/ after editing. If it’s green, the case is structurally sound.

The content-integrity rule

Non-negotiable

Never fabricate evidence that imitates a real outlet. A mocked-up Bangkok Post headline gets photographed at a booth and shared out of context — and a workshop about misinformation loses its footing the moment its own evidence turns out to be fake. Real cases cite real URLs. Invented evidence (the NovaBrew case) is flagged fictional: true and renders a visible FICTIONAL badge.

Case 3 does contain a fabricated court citation — Hendricks v. Meridian Logistics Corp. — but it appears only as the AI’s output, never as evidence, and the reveal explicitly debunks it. That’s the lesson, not a leak.

05 — The design underneath the contentThe five-case arc

Each case teaches a different failure mode, so players leave with a checklist rather than a vague “AI is sometimes wrong.” The order is deliberate, and the back half deliberately breaks the habit the front half builds.

CaseTeachesRetrieval
🟢Artemis IIStale knowledge — the answer was true1 doc missing
🟡Milan-Cortina medalsFabricated specifics — right shape, invented numbers1 doc missing
🟠The fake citationRight answer, invented source1 doc missing
🔴NovaBrewFlawed reasoning — every number correct, conclusion wrongnothing missing
⚫The goblin sharkThe AI is right. Reflexive doubt is the trap.nothing missing

By case 4, players have learned to hunt for the missing document — and that heuristic stops working. Case 4 retrieves cleanly and is still wrong, because the flaw is in the reasoning, not the retrieval. Then case 5 retrieves cleanly and isn’t wrong — and a room primed by four cases to distrust the machine will flag a true answer on reflex.

The arc reads: check the date → check the numbers → check the source → check the reasoning → and then check yourself. That last one is the closing line of the workshop.

Design decisions the team may want to revisit
  • Soft timer. The app never hard-cuts or auto-submits. A countdown creates tension but locks nobody out. A workshop teaching careful thinking must not punish it.
  • Speed is a tiebreaker only. Scoring is capped so one extra correct answer always beats any speed advantage. Rewarding snap judgments would be a strange thing for this workshop to do.
  • Codenames, not names or emails. No lead capture — it adds friction and a salesy smell at a welcoming booth.
  • Answers survive a wifi blip. A failed submit is queued in the browser and retried. The player is never blocked by the network.

07 — Honest statusWhat’s not done

  • Someone needs to click through /dashboard in a real browser. The panels and the L toggle are unit-tested but have never been eyeballed. Two minutes; do it before the day.
  • Fact-check the Case File summaries. The underlying facts were researched with live search, but a few documents paraphrase real articles (NBC, ABA, NPR). Confirm each summary matches what that specific article actually says. In a workshop about fabricated sources, our own evidence has to be airtight.
  • Test the venue wifi with two laptops. The real risk isn’t the code — it’s client isolation, where the network gives every laptop internet but blocks laptop-to-laptop traffic. Your server becomes invisible and there is no fix on the day. Keep a phone hotspot as fallback.
  • The cases are a draft. They’re sourced and structurally valid, but they’re meant to be argued with. That’s what this document is for.
